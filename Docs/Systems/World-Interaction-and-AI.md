# World Interaction, Gathering, and AI

## Resource nodes
AERResourceNode is a replicated actor that implements UERInteractableTarget. Configure ResourceItemId, RemainingQuantity, and QuantityPerGather on each placed or spawned node. Gathering runs on the server and reduces the node's available quantity only when the inventory accepts the item.

Before production, add a data-driven resource definition, gather duration/animation, tool requirements, skill checks, depletion visuals, respawn scheduling, contention locks, anti-bot rate limits, and persistent resource state. The current implementation is a starter example.

## Enemy character
AEREnemyCharacter provides replicated movement and configurable XP reward, base damage, and AI profile identifier. It intentionally does not instantiate a Behavior Tree or award XP on death yet; those behaviors should be implemented in a dedicated AI/death-reward flow with server-side attribution and duplicate-award protection.

## Interaction rules
- Client input should only request an interaction.
- The server must re-check target validity, range, eligibility, inventory capacity, and ownership.
- Do not trust client-supplied item quantities, rewards, or target state.
- Add line-of-sight and rate-limit checks for interactables where appropriate.
- Persist gathering and reward results through server-side transaction boundaries when economy or progression value is involved.

## Unreal integration
1. Create Blueprint children of AERResourceNode and AEREnemyCharacter.
2. Assign static meshes, collision, materials, animation classes, and UI prompts in the editor.
3. Configure AIController and Behavior Tree assets for enemy behavior; those assets are not generated by the current Python shell script.
4. Test multiplayer contention, inventory-full failures, and resource depletion with a dedicated server.
